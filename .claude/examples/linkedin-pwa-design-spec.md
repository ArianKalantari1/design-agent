# Design Spec — LinkedIn Content Agent (PWA)

Generated by design-brief · 2026-05-26

---

## Colour System

| Token | Hex | Usage |
|---|---|---|
| `primary` | `#2B6349` | CTAs, active states, links, key UI moments |
| `background` | `#F8F7F4` | Page/app background — warm off-white, not clinical |
| `surface` | `#FFFFFF` | Cards, panels, modals — clean contrast against background |
| `text` | `#1A1917` | Body copy, headings — warm near-black, never pure black |
| `muted` | `#9B9690` | Timestamps, captions, secondary labels, placeholder text |
| `accent` | `#C4722A` | Content pillar badges, series tags, active calendar entries |
| `border` | `#E5E2DB` | Card borders, dividers, input outlines |

**Justifications:**
- `primary` deep forest green — "calm authority." Not typical SaaS blue or AI purple. Green signals growth and expertise without aggression. Informed by the user's rejection of corporate SaaS and AI-signalling colour.
- `background` warm off-white — "calm." Borrowed from the Notion tradition: not a harsh white, not a dark surface. Writing happens on paper, and this background feels like paper.
- `text` warm near-black — "sharp." High contrast without the harshness of pure black. Keeps focus on the words.
- `accent` warm amber — "personal." Content pillars are the user's intellectual territory — the amber signals warmth and ownership without competing with the primary.
- `border` barely-there warm — shadow replacement. Separation is handled by border colour, not drop shadows. Keeps the interface calm and flat.

---

## Mode

**Light default.**

The primary writing and interview surfaces must default to light. Dark mode is supported as a user preference but never the default. Justification: the user stated this explicitly. Dark mode defaults signal "developer tool" — this product is a content professional's workspace. Writing on a warm off-white background feels intentional and human.

## Typography

| Element | Font | Size | Weight |
|---|---|---|---|
| h1 | Fraunces | 2.25rem | 600 |
| h2 | Fraunces | 1.5rem | 600 |
| h3 | Fraunces | 1.125rem | 600 |
| body | DM Sans | 1rem | 400 |
| small | DM Sans | 0.875rem | 400 |
| UI labels | DM Sans | 0.875rem | 500 |

**Pairing justification:**
- **Fraunces** (heading) — an optical variable serif with genuine character. Editorial rather than corporate. Used in writing-forward contexts. Signals "content" and "craft" rather than "SaaS dashboard." The contrast between a distinctive serif heading and a clean sans body is how Notion's own brand communicates "this is a writing space."
- **DM Sans** (body) — clean, open, highly readable at body size. Slightly warm compared to Inter. Disappears when you're reading content — which is what "the content is the UI" demands. Does not compete with Fraunces; it serves it.

## Spacing System

Base scale: `4 · 8 · 12 · 16 · 24 · 32 · 48 · 64px`

**Density: Two registers within one product**

- **Writing / interview surfaces:** generous — prefer 24–64px. The blank-page feel is not accidental. Space communicates that the user's words matter. Never compress the writing area to fit more UI.
- **Content library / calendar / pillar manager:** standard — prefer 8–24px. This is a reference view. Tighter spacing is appropriate because the user is scanning, not composing.

Both registers must be consistent within their context. Do not mix dense and generous spacing on the same screen.

---

## Border-Radius Convention

Derived from "calm, sharp, personal" + Notion and Linear as reference products.

- **Interactive** (buttons, inputs, selects): `rounded` — 4px. "Sharp" demands restraint. Notion and Linear both use minimal radius for interactive elements. Nothing decorative.
- **Container** (cards, panels, modals): `rounded-md` — 6px. One step up from interactive. Slightly softer but still precise.
- **Pill** (content pillar badges, series chips, tags): `rounded-full` — justified. Content pillars need to read as distinct categorical labels, not generic UI chips. The pill shape signals "this is a named thing that belongs to you."

Do not apply `rounded-lg`, `rounded-xl`, or `rounded-2xl` anywhere. These read as AI-generated defaults for this product.

---

## Shadow & Elevation System

Derived from "calm, sharp" + Notion (border-not-shadow) and Linear (near-flat).

| Level | Elements | Treatment |
|---|---|---|
| Level 0 (flat) | Inputs, inline elements, nav items | `border border-[#E5E2DB]` only — no shadow |
| Level 1 (subtle) | Cards, panels, post draft containers | `shadow-sm` + `border border-[#E5E2DB]` |
| Level 2 (lifted) | Modals, command palette, dropdowns | `shadow-md` — no border needed at this elevation |

**Justification:** "Calm" and "sharp" both push toward flat. Notion uses borders for card separation, not shadows. The primary elevation signal in this product is background colour contrast (`#F8F7F4` vs `#FFFFFF`) — shadows support that, they do not carry it. Do not use `shadow-lg` or `shadow-xl` on any element.

## Icon Library

**Lucide** — `lucide-react`

Justification: clean 1.5px stroke, consistent optical weight, natural fit with shadcn/ui, has the exact vocabulary needed (edit, calendar, archive, settings, user, plus). Used in Linear-adjacent tools. Pairs with DM Sans body text without weight conflict.

- Inline / UI icons: `w-4 h-4`
- Standalone action icons: `w-5 h-5`
- Never scale above `w-6 h-6` — icons are navigation aids, not features

---

## Component Library

**shadcn/ui only.**

Justification: this product is fundamentally a writing and reading tool. Every screen is about composing content, reviewing drafts, or managing a content strategy. No specialist overlay library serves this better than shadcn/ui primitives used carefully. Tremor is for data dashboards — not appropriate. Magic UI adds motion that would conflict with "calm." Aceternity is for marketing pages. Custom components on shadcn/ui primitives will produce a more distinctive, text-forward result than any overlay library.

## Layout Principles

1. **Single-focus screens.** Every screen has one primary action — answer a question, review a draft, approve a post, check a pillar. Never two CTAs competing. Layout is built around making the one primary action effortless. Secondary actions (edit, archive, reschedule) are present but visually subordinate.

2. **Content at the centre, chrome at the edges.** Post drafts, interview questions, and voice feedback occupy the widest comfortable reading measure (max ~65ch). Navigation, status indicators, and toolbars live at the edges and stay visually quiet. The user's words get the prime real estate.

3. **Navigation is ambient.** The app has sections (interview, drafts, pillars, calendar) but users are not navigating features — they are moving between phases of one workflow. Nav stays in muted text, no icon badges, no active-state notifications, no sidebar expanding to reveal sub-menus.

4. **Progress is felt through content, not announced.** No "X posts published," no completion rings, no streak counters. The richness of the content library IS the progress indicator. A user who has 12 polished posts in three pillars knows they've made progress — we do not need to score it for them.

5. **Two spatial registers, never mixed.** The interview/writing flow (generous: 24–64px spacing, wide content measure, minimal surrounding UI) and the content management view (standard: 8–24px, tighter list rows, more information per screen) are distinct. Mixing them on the same screen signals the product doesn't know what it is.

## Do-Not-Do List

1. **No engagement metrics on writing surfaces.** No "estimated read time," "predicted engagement," or "post score" near a draft. These gamify writing and signal generic AI tool. The post exists to express expertise — not to score well on an algorithm.

2. **No template library and no "generate N posts" buttons.** A template browser signals the opposite of authentic voice. If it appears in the UI, users will click it and produce content indistinguishable from everyone else. Content is generated from interview answers only. The generation mechanism is never exposed as a feature.

3. **No dark backgrounds on writing and interview surfaces.** Even if dark mode is enabled, the interview question area and post draft surface should use the warm off-white background. Writing happens on paper. The one exception: the user has explicitly opted into a dark writing environment — an intentional mode, not a default.

4. **No social media scheduler patterns.** No "optimal time to post" heatmaps, no bulk-schedule queues, no platform icons with status checkboxes. The calendar is a content strategy tool — which pillar, which series, which narrative arc. It is not a posting queue.

5. **No AI-signalling visual decoration near user content.** No sparkle icons (✨), no "AI is writing..." shimmer animations on the draft surface, no purple or teal gradient accents alongside generated copy. The AI is invisible infrastructure. The content should feel entirely like it came from the user — because it did.
